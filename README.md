# C64 Program Collection

Forty-five small, polished programs for the Commodore 64, written in stock Commodore BASIC V2 and 6502 machine code. The collection mixes arcade action, puzzles, simulations, mathematics, physics, creative tools, music, utilities, and visual effects. Every entry is self-contained and runs on an ordinary PAL or NTSC C64 without a cartridge or BASIC extension.

Browse and run the collection at [c64.p20.dev](https://c64.p20.dev).

## Running the programs

Start the local browser app with Docker Compose:

```text
docker compose up --build -d
```

Open [http://localhost:8134](http://localhost:8134), or visit the hosted collection at [c64.p20.dev](https://c64.p20.dev). The app runs the VICE x64sc core through WebAssembly and downloads the selected PRG through its own backend. Click inside the emulator to enable keyboard input and sound. Direct keyboard input is enabled by default, mouse locking is disabled, and moving the pointer anywhere over the emulator reveals its control bar.

The repository is mounted read-only at `/programs`. Add a manifest entry and its source and PRG files, then click **Refresh**; the app does not need to be rebuilt. The overview renders programs in small batches and is ready to scale without creating every card at once. The default host port is configured as `8134` in `.env`.

On a Commodore 64, transfer a PRG to disk or another supported medium, then use:

```text
LOAD"PADDLE-BALL.PRG",8
RUN
```

Substitute the filename and device number as needed. Machine-code PRGs include a small BASIC `SYS` launcher, so the same `RUN` command starts them.

## Building machine-code programs

The assembly sources use ACME syntax. Build every machine-code PRG with the isolated tools profile; no local assembler installation is required:

```text
docker compose --profile tools run --rm assembler
```

The tools profile is opt-in and is not started by the normal app command.

## Capturing screenshots

Every program has a recipe in `screenshots.json`. The recipe waits for the emulator, focuses it, dismisses the splash screen, performs any program-specific actions, and captures a clean 960×720 PNG from the browser compositor. Screenshots are stored as `screenshot.png` beside each program and appear automatically in the grid view; no web-app rebuild is required.

The website serves screenshots as WebP at quality 90. PNG originals remain untouched. Converted images are generated on first request and retained in the persistent `screenshot-cache` Docker volume. Content-based URLs invalidate browser caches when an original changes; subsequent requests reuse the WebP file without converting it again.

Capture screenshots that do not exist yet:

```text
docker compose --profile tools run --rm screenshots
```

Capture one program again, or rebuild the whole gallery:

```text
docker compose --profile tools run --rm screenshots haunted-night --force
docker compose --profile tools run --rm screenshots --force
```

When adding a program, add its slug to `screenshots.json`. In most cases an empty object uses the collection's standard splash-screen recipe. Add explicit timed key actions when a program needs a particular scene. Always run and inspect the new screenshot before committing the program.

## Source format

Each program directory contains a loadable `.prg` and its readable source:

- BASIC programs use line-numbered, uppercase `.bas` files compatible with stock Commodore BASIC V2. Their PRGs are tokenized at the normal `$0801` BASIC load address.
- Machine-code programs use commented ACME `.asm` files. Their PRGs also load at `$0801`, where a short BASIC line starts the 6502 code with `SYS`.

New programs must open with an English splash screen containing a highlighted title, a short description, the full URL `https://c64.p20.dev`, the release date, and a prompt to continue with Space. The splash must include a **Controls** heading and visually distinguish its keys from their explanations. Gameplay instructions belong on the splash screen rather than occupying permanent rows in the running program.

All programs are self-contained and designed for ordinary PAL and NTSC C64 hardware as well as VICE-compatible emulators.
